# ADR-002: Accounts design (story 1) and disposition of the lane findings

- Run: REBUILD-MINIDON, story 1, L1-accounts
- Author: design-agent, 2026-11-13
- Status: PROPOSED (gate is a human decision, I-23)
- Depends on: `adr-001.md` (platform, formats, contract, harness, threat-model delta)
- Labels (I-05): STATED = from a human decision or the baseline gate record, source given. DERIVED = designed or inferred by design-agent. Rules cited as capability/BR id.

## 1. Context

Accounts owns registration, sign-in, the token store, profile lookup and update, and the identity API other capabilities call. STATED (baseline gate CF-004): `get_by_username` is a stable identity API owned by `L1-accounts`. Behaviour is copied as-is (STATED, ticket). Rules in scope: `L1-accounts/BR-001` to `BR-014` (BR-014 only sets the locked flag, the mechanism lives in Following).

## 2. Design

All DERIVED, except where a STATED source is named.

### 2.1 Module shape

`accounts` module with `routes` (axum handlers, five endpoints), `service` (rules), `store` (sqlx queries) and `identity` (public API: `get_by_username`, `get_by_id`, `current_account` extractor logic). Other modules depend only on `identity`. No other module reads the accounts table or the token table.

### 2.2 Rule to design mapping

| Rule | Design |
|---|---|
| `L1-accounts/BR-001` (STATED) | Lower-case (Unicode), match `^[a-z0-9_]{1,30}\n?\z`, no strip. Deliberate trailing-newline copy (adr-001 D5). Failure is 422 with `{"detail": [...]}` or `{"error": msg}` exactly as Python does per case, proven by the harness |
| `BR-002`, `BR-003` | Email contains `@` (trimmed first). Password length counted in code points, minimum 8. Weak policy copied (adr-001 weaknesses) |
| `BR-004`, `BR-005` | Uniqueness checked case-insensitively including suspended accounts, with the same 409 messages "Username is taken" and "Email is already registered". Email is checked after username as in Python (verified by the harness) |
| `BR-006` | Count-then-insert, first account becomes admin. Same race, documented, not fixed |
| `BR-007` | PBKDF2-HMAC-SHA256, 100,000 iterations, 16-byte random salt, `<salt hex>$<digest hex>` lower-case hex, UTF-8 raw. Constant-time compare of the hex strings with `subtle`. No rehash |
| `BR-008` | Unknown user and wrong password both 401 with the same body. No dummy hash, no throttle (copied) |
| `BR-009` (STATED) | Suspended account with a correct password gets 403 "This account is suspended". Order of checks as Python (`accounts/service.py:60-68`) |
| `BR-010` | Token is a random key stored in clear text, expiry 30 days, naive UTC. Expired when `expires_at <= now` |
| `BR-011` | The extractor reads token, account and suspension from the database on each request. Expired or suspended means signed-out (anonymous) for optional routes and 401 for required routes. No cache |
| `BR-012` | Normal lookups treat suspended accounts as not found. `identity` has an explicit `include_suspended` variant used only by Moderation |
| `BR-013` | Display name at most 30, bio at most 500, counted in code points |
| `BR-014` | Stores and returns the locked flag only |

### 2.3 Error mapping

Domain errors go through one platform error type with the status codes of adr-001 D3. Framework validation maps to the 422 `detail` shape. Panics map to the 500 body. Nothing logs bodies, the `Authorization` header, tokens or passwords.

### 2.4 Tests for story 1

The parity suite covers all of `BR-001` to `BR-014`, each first green against Python `e1fbd3a`. Mandatory extra cases: the trailing-newline set, non-ASCII names, passwords and bios, multi-byte length limits, Python-to-Rust and Rust-to-Python sign-in, token expiry at the exact instant, header case and whitespace, suspended-account next-request behaviour, tampered hash row keeps the server up, large body, 50 wrong passwords, first-account admin, and the five lone-surrogate and range inputs from adr-001 D3 under their recorded deviation.

## 3. Disposition of the 8 major lane findings (OP-08)

STATED (OP-08, DEMO): work through them in design, before build. "Addressed" means the design handles it. It does not mean a human approved it.

| Finding | Applies to Accounts | Disposition |
|---|---|---|
| S-01 trailing-newline username | Yes, directly | Addressed. adr-001 D5 and threat row 3. Parity cases and code comment. Follow-up F-A |
| S-02 unlisted authentication weaknesses | Yes | Addressed. Listed as carried-forward weaknesses F-C, F-D, F-G (adr-001 section 3). No throttle, same 409 messages, no dummy hash, explicit body limit decision pending a human |
| S-03 Python 500 paths and oracle | Yes (register, sign-in) | Proposed deviation to 4xx recorded in adr-001 D3, needs a human decision before build |
| S-04 execution-time controls | Yes (harness, test data) | Addressed in adr-001 D4 and threat row 15: oracle started outside the reference repo, `PYTHONDONTWRITEBYTECODE=1`, `git status --ignored` proof, frozen oracle deps, sanitised data definition, security-sensitive modules (hashing, tokens, extractors, staff checks, `can_view`) reviewed by another agent and merged by a human |
| S-05 Rust-stack threats | Yes | Addressed. Panic handling, header parsing, bound SQL, no auth cache, ReDoS note in adr-001 D1, D3 and threat rows 7, 12, 14 |
| F-01 15 endpoints without a journey | Partly. `GET /accounts/me` and `GET /accounts/{username}` are Accounts | Addressed for Accounts: the two routes are in the story 1 parity suite (2.4). The other 13 routes belong to later stories and each story's spec must cover its routes. Planning owns the journey document update (flows are research files and untouched here) |
| F-02 19 to 38 versus 16 to 34 days | No | Not a design matter. STATED (OP-08, DEMO): `estimate.json` stays the authority at 16 to 34 days. Design adds no duration |
| F-03 trailing-newline in flows | Yes | Same case as S-01. J1 and J5 need the case, to be added by the plan and spec stages. This ADR names it as a required parity case and part of the Unicode input class |

The minor findings that touch Accounts are also handled: S-06 (reverse direction hash tests, no rehash), S-07 (two-step admin and unsuspend no-op inherited by Moderation), S-08 (labels split here between STATED and DERIVED), S-09 (frozen oracle and crate criteria), S-10 (data at rest unchanged), F-05 (status codes 401, 403, 409, 422 for Accounts are named in the table above and must be confirmed against Python by the harness, not asserted). S-11 (rate-limit counting details: deleted rows count, boosts excluded) is inherited by Posting.

## 4. Consequences and open items

- Story 1 can be specced and planned from this ADR once the five human decisions in adr-001 section 5 are made.
- The look-alike username, weak policy and hashing, no throttling, clear-text tokens and no revocation ship in Rust exactly as in Python, and are tracked as follow-ups F-A to F-I in adr-001.
- OP-10 (stale baseline record) is not a design matter and stays DEFERRED to before release.
